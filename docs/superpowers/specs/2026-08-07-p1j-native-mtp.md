# P1-J Native MTP — Design Specification

**Date:** 2026-08-07
**Base:** `p1i/native-model-shell@e67a8f6b1203c417724f8e47f74dd5f9af56dab5`

## Goal

Implement the single DeepSeek V4 Flash Multi-Token Prediction block as a portable FP32 batch-one/token-one runtime. P1-J is deliberately standalone: it consumes the final base-model HC streams emitted by P1-I plus the current token id, and owns only the mutable state of the extra MTP decoder layer.

## Source review and decisions

- **Target P1-I:** KEEP the caller-owned embedding and LM-head tensors and the final `[hc_mult, hidden]` base streams; do not duplicate the base model.
- **Target P1-H:** KEEP the complete transactional decoder-layer runtime for the MTP block body.
- **Mini-oracle `MTPBlock`:** REWRITE the pre/post glue in C99: embedding RMSNorm + `e_proj`, stream RMSNorm + `h_proj`, broadcast/sum, decoder step, HyperHead, output RMSNorm and shared LM head.
- **Official DeepSeek V4 Flash `MTPBlock`:** preserve `e = enorm(embed(input_ids))`, `x = hnorm(x)`, `e_proj(e).unsqueeze(2) + h_proj(x)`, a full extra `Block`, then shared head with MTP-owned HC-head parameters and final norm.
- **Official converter:** preserve shared embedding/head semantics; converted MTP-local copies of embedding/head are skipped.
- **q36 mini-oracle design branch:** design input only; no MTP implementation to port.

No official source code or checkpoint bytes are copied.

## Public contract

`DSV4MTPConfig` contains vocab/hidden/HC sizes, `max_seq_len`, HC/norm epsilons and one `DSV4DecoderLayerConfig`. The decoder config must describe the extra MTP layer, use learned routing for the production profile, and use compression rate zero for the reviewed Flash schedule.

`DSV4MTPWeights` contains:

- shared `embedding_weight [vocab, hidden]`;
- shared `lm_head_weight [vocab, hidden]`;
- MTP `embedding_norm_weight [hidden]` and `hidden_norm_weight [hidden]`;
- `embedding_proj_weight [hidden, hidden]` and `hidden_proj_weight [hidden, hidden]`;
- one `DSV4DecoderLayerWeights`;
- MTP HyperHead `fn [hc, hc*hidden]`, `base [hc]`, `scale [1]`;
- MTP output norm `[hidden]`.

The runtime exposes create/reset/destroy plus `dsv4_mtp_step_f32`. One successful call consumes exactly one absolute position. Outputs are final MTP streams, vocabulary logits and the MTP decoder route pairs/trace for diagnostics.

## Numerical order

For each token:

1. lookup the shared embedding row;
2. weighted RMSNorm embedding;
3. dense `e_proj`;
4. weighted RMSNorm every HC hidden stream independently;
5. dense `h_proj` independently per HC stream;
6. broadcast projected embedding to every HC stream and add projected hidden streams;
7. run the owned P1-H decoder at the runtime absolute position;
8. run the MTP HyperHead: unweighted RMS over flattened HC streams, dense mixes, sigmoid + `hc_eps`, weighted stream collapse;
9. weighted output RMSNorm;
10. dense shared LM head.

All accumulation is FP32 reference arithmetic with finite/overflow checks consistent with P1-H/P1-I.

## Transactionality

The MTP decoder executes on a deep clone. The live decoder state and `next_position` are committed only after the final vocabulary logits are finite. Failure in pre-projection, decoder, HyperHead, final norm or LM head leaves runtime state, output buffers and route diagnostics unchanged. A failed call can be retried at the same position.

## Canonical fixture

The fixture generator uses the real mini-oracle `MTPBlock` with the reduced P1-I configuration. It fills shared embedding/head and every MTP-owned tensor with deterministic binary-fraction weights. Base streams are generated by the already canonical P1-I base model path rather than invented independently.

The fixture covers at least 20 incremental tokens so the rate-0 MTP attention crosses raw sliding-window wraparound. It records final MTP streams, logits, argmax and learned route expert/weight pairs.

## Non-goals

No combined base-model+MTP all-or-nothing transaction, greedy generation loop, tokenizer/chat template, checkpoint binding, FP8/FP4 decode, tensor parallelism, Vulkan or SSD streaming is included in P1-J. Combined model transactionality belongs to the next integration increment.
