# DeepSeek V4 CPU Routing and mHC Design

Date: 2026-08-06

## Scope

P1-A introduces the first native DeepSeek-specific FP32 operators in portable C99:

- stable `sqrt(softplus(x))`;
- the mini-oracle hash routing schedule;
- learned top-k routing with correction bias;
- unweighted RMS normalization and manifold-constrained Hyper-Connections;
- the exact Sinkhorn normalization order used by the canonical mini-oracle.

This increment does not implement attention, experts, MTP, a decoder layer, a full C mini-model, checkpoint-backed execution, Vulkan or SSD streaming.

## Canonical source

The behavioral reference is the merged FP32 mini-isomorphic oracle at
`13952eff5dcf75ce75e692d5a03e714e47de2fd4`, especially:

- `tools/dsv4_mini/reference.py`;
- `tests/python/test_dsv4_mini_routing.py`;
- `tests/python/test_dsv4_mini_hyperconnection.py`;
- `tools/dsv4_mini/initialization.py`.

The C fixture is generated by instantiating those canonical classes with explicit tensors. No PyTorch RNG sequence is reproduced in C.

## Routing semantics

Hash routing preserves the mini-oracle formula and slot order:

```
start = token_id * 5 + layer_idx * 3
expert(slot) = (start + slot * 7) mod num_experts
```

The API rejects a requested top-k that exceeds the unique cycle induced by step 7.

Learned routing computes FP32 logits, then `sqrtsoftplus(logit)`. Correction bias participates only in expert selection. Route weights are gathered from the unbiased scores, normalized with the canonical `1e-20` denominator guard and multiplied by `route_scale`.

PyTorch `topk(..., sorted=False)` does not define a portable slot order. The C API therefore canonicalizes the selected set by descending corrected score and lower expert id for exact ties. Generated vectors verify that this ordering contains exactly the same selected experts as the canonical unsorted result and that the test inputs have no ties.

## Hyper-Connection semantics

For one `[hc_mult, hidden]` group, C preserves the canonical sequence:

1. flatten all streams;
2. unweighted RMS normalization;
3. one row-major linear projection split into pre, post and `hc_mult × hc_mult` combination logits;
4. `pre = sigmoid(pre_w * pre_scale + pre_b) + eps`;
5. `post = 2 * sigmoid(post_w * post_scale + post_b)`;
6. row softmax of combination logits, then `+ eps`;
7. initial column normalization;
8. `iterations - 1` row/column normalization pairs;
9. final row normalization;
10. collapse streams using pre weights.

The output matrix must satisfy the same `2e-4` row/column stochasticity gate as the Python oracle.

## Numerical and safety rules

- Stable softplus and sigmoid avoid overflow.
- FP contraction is disabled in parity builds.
- Size products are overflow checked.
- Non-finite inputs are rejected before selection or Sinkhorn.
- Route IDs are exact; FP32 outputs use fixture-specific tolerances no looser than `2e-4`.
- GCC analyzer, ASan and UBSan are mandatory.

## Acceptance

P1-A is accepted when:

- generated vectors reproduce the checked-in header byte-for-byte;
- GCC and Clang pass route IDs, route weights, mHC outputs and stochasticity gates;
- correction bias changes the selected set while weights remain sourced from unbiased scores;
- Make, CMake/CTest and the full existing CI remain green;
- the existing 24-test mini-oracle workflow remains green.
